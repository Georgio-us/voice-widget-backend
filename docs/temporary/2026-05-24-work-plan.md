## 2. Houses, Land Plots, Sotkas

### 2.1 Data Model

Needed entities:

- `area_m2`: area of apartment/commercial/house building.
- `land_area_sotka`: land plot area in sotkas.

Rules:

- `apartment`: use `area_m2`.
- `commercial`: use `area_m2`.
- `house`: use `area_m2` for house area and `land_area_sotka` for plot area.
- `land`: use `land_area_sotka`; do not treat it as `area_m2`.

Decision to make:

- Whether `land_area_sotka` is a real DB column or stored inside `features` temporarily.
- Preferred production path: real explicit field, because filters and imports need stable querying.
- Current quick path: store in `features.landAreaSotka` and `features.land_area_sotka`, with API pass-through.

### 2.2 Add/Edit Object Payload

Needs to support:

- House: send and save both `area_m2` and `land_area_sotka`.
- Land plot: send and save `land_area_sotka`.
- Edit mode: read saved `land_area_sotka` back into the form.

Risk if not fixed:

- Land plots can be saved as `area_m2` even when user entered sotkas.
- House plot area can be lost because old contract has only one area field.

### 2.3 Manual Filters

Supported payload fields:

- `landAreaFrom`
- `landAreaTo`

Filtering rules:

- `house`: house area filter uses `area_m2`; land plot area filter uses `land_area_sotka`.
- `land`: visible area filter means `land_area_sotka`, not `area_m2`.
- Switching property type already clears filter values on UX side; backend applies the corresponding query interpretation.

Implementation status:

- Frontend converts manual `landAreaFrom` / `landAreaTo` into `minLandArea` / `maxLandArea`.
- Backend `/api/cards/search` filters `minLandArea` / `maxLandArea` against normalized `land_area_sotka`.

### 2.4 Canonical AI Extraction

AI/query contract fields:

- `landArea`
- `landAreaMin`
- `landAreaMax`

AI should understand examples:

- `участок 10 соток`
- `земля 6 соток`
- `дом 120 квадратов и 6 соток`
- `дом с участком`
- `участок от 5 до 10 соток`

Strict rule:

- Do not mix house/building area and land plot area.
- `area` means building/internal area.
- `landArea` means plot area.

Implementation status:

- Structured extraction schema includes `landArea`, `landAreaMin`, `landAreaMax`.
- Prompt explicitly separates building area from land plot area.
- Frontend canonical patch maps these fields into `minLandArea` / `maxLandArea`.

### 2.5 OLX Import

Needed mapping:

- House: map building area to `area_m2`, plot area to `land_area_sotka`.
- Land plot: map plot area to `land_area_sotka`.

Confirmed OLX structured key:

- `land_area`: plot area in sotkas for land plots and houses.

Needed unit normalizer:

- `1 сотка = 100 м²`
- `1 га = 100 соток`
- Accept variants: `сотка`, `сотки`, `сот.`, `га`, `м²`, `м2`.

Potential quick path:

- First inspect what OLX already returns structurally for houses/plots.
- If OLX has structured land-area attributes, map those directly.
- Only parse text descriptions as a fallback, not as the primary method.

## 9. Government Program Detection Decision - 2026-05-24

Accepted implementation boundary:

- Do not parse `description` for government programs.
- Detect government programs from explicit UX checkboxes and from `title` only.
- OLX `єОселя` should use the official structured `eoselia` attribute when present.
- OLX `єВідновлення` has no reliable structured field, so it is detected from `title` only.

Title heuristics are intentionally narrow:

- `єОселя`, `еОселя`, `є Оселя`, `е Оселя`, `є-Оселя`, `е-Оселя`.
- `єВідновлення`, `еВідновлення`, `є Відновлення`, `е Відновлення`, `є-Відновлення`, `е-Відновлення`.
- Russian-style fallback for title only: `е видновление`, `е-видновление`, including one or two `н` variants.
- Case-insensitive.

Explicitly not supported for now:

- English/translit variants such as `vidnovlen`.
- Searching `description`.
- Broad keyword `відновлення` without the `є/е` prefix.

Reason:

- Avoid broad description parsing, false positives, and extra dictionary complexity.
- Keep product logic deterministic and easy to test.
