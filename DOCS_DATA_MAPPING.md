# OLX → продукт: перечень полей и группы данных

Документ-опора: **что отдаёт OLX Partner API** (v2, схема `Advert` в OpenAPI) и **как мы классифицируем** поля для фильтров, обратной стороны карточки и архива.  
Реализация импорта/маппера описывается отдельно; здесь только перечень и правила раскладки.

**Источник схемы API:** `https://developer.olx.ua/swagger/v2/partner_api.yaml` → `components.schemas.Advert`.

---

## Часть A. Полный перечень полей объекта объявления (OLX)

Ниже — поля верхнего уровня ответа **одного объявления** в списке/деталях (модель `Advert`). Массив **`attributes`** категорийно-зависимый: набор `code` задаётся метаданными категории (недвижимость, авто и т.д.).

| Поле OLX | Тип (по OpenAPI) | Что это даёт |
|----------|------------------|---------------|
| `id` | integer | Внутренний идентификатор объявления на OLX. |
| `status` | string (`new`, `active`, `limited`, `removed_by_user`, …) | Жизненный цикл объявления (черновик, активно, снято и т.д.; в ответе реального API набор статусов может быть шире примера в схеме). |
| `url` | string | Публичная ссылка на страницу объявления на сайте OLX. |
| `created_at` | string (дата/время) | Когда объявление создано. |
| `activated_at` | string | Когда последний раз активировали. |
| `valid_to` | string | До какого момента объявление действует (пакет/размещение). |
| `title` | string | Заголовок объявления. |
| `description` | string | Текст описания. |
| `category_id` | number | Категория размещения; от неё зависят доступные **коды** в `attributes`. |
| `advertiser_type` | `private` \| `business` | Частное лицо или бизнес. |
| `external_id` | string | ID объявления во внешней системе партнёра (если постили через интеграцию). |
| `external_url` | string | URL во внешней системе. |
| `contact` | object | Контакт продавца: `name`, `phone` (телефоны могут быть несколько в одной строке). |
| `location` | object | Геолокация объявления: обязателен **`city_id`**; опционально **`district_id`**, **`latitude`**, **`longitude`**. В канонической схеме **нет** отдельного поля `street` — улица обычно приходит в **`attributes`**. |
| `images` | array | Элементы с полем `url` — ссылки на фото. |
| `price` | object | Цена в категориях с ценником: `value`, `currency`, `negotiable`, `trade`, `budget`. |
| `salary` | object \| null | Для вакансий и т.п.: диапазон, валюта, тип (месяц/час). |
| `attributes` | array | Список пар `{ code, value?, values?[] }` — **все параметры карточки категории** (комнаты, площадь, comfort, heating, …). Конкретные `code` задаёт категория. |
| `courier` | boolean \| null | Доставка (не все регионы). |
| `auto_extend_enabled` | boolean | Автопродление срока размещения. |
| `product_safety_regulation` | object | Регуляторные поля (EU и отдельные страны). |

**Итого по OLX:** фиксированный **каркас** объекта выше + **произвольный набор** строк в `attributes` с кодами из справочника категории.

**Замечание по именам из PM:** поля вроде `multimedia`, `furniture`, `household_appliances`, `street` / `street_address`, `total_area`, `comfort`, `heating`, `repair` и т.д. в OpenAPI на верхнем уровне **не перечислены** — их нужно искать как элементы **`attributes[]`** с соответствующими **`code`** (их перечень подтверждается выгрузкой метаданных категории недвижимости или реальными ответами API).

## Часть B. Три группы (продуктовая классификация)

### ГРУППА 1 — АКТИВ (фильтры и поиск, Mini App)

Данные участвуют в фильтрации/поиске; маппятся в системные поля БД / верхний уровень `features` (по мере внедрения маппера).

| Логическое поле | Источник OLX | Назначение |
|-----------------|--------------|------------|
| **Operation type** | `category_id` → детерминированный mapping в `data/olx/category-map.json` | Тип сделки для фильтра. |
| **Property type** | `category_id` (+ `attributes` fallback) → `apartment` / `house` / `commercial` / `land` / `parking` | Тип недвижимости. |
| **District name** | `location.district_id` → `data/olx/district-map.json`; если `district_id = null`, fallback из подтверждённых `location.city_id` локализаций | Фильтр по району/локации. |
| **Price USD** | `price.value` (+ `price.currency`) → сумма **в долларах** | Фильтр по цене; при необходимости конвертация в USD. |
| **Rooms** | Квартиры: **`number_of_rooms_string`** (slug, см. §C.1). Дома: **`number_of_rooms`** (число в `value`). Плюс **`layout`**: `studio` — учитывать в нормализации комнатности. | Количество комнат для фильтра. |
| **Total area** | **`total_area`** | Общая площадь, м² (`value` может быть `"36.5"`). |
| **Floor** | **`floor`** | Этаж объекта. |
| **Has balcony** | В выгрузке **нет** отдельного `attributes` с балконом. Не путать с **`apartments_dev_type` = `comfort`** — это **класс жилья**, не «есть балкон». Балкон/паркинг: искать в других категориях OLX, в `values[]` других кодов или fallback по **title/description**. | Фильтр «балкон/лоджия» — **TBD по коду** после расширенной выборки. |
| **Has parking** | Аналогично — в этой выборке кода не видно. | **TBD**. |
| **Complex name** | **`zkh`** (текст ЖК с OLX) **и/или** title/description + **справочник ЖК**. | Приоритет: структурное поле `zkh`, затем парсинг текста. |

*Дополнительно в выдаче OLX есть `location.city_id`; для согласованных фильтров по городу его тоже предстоит резолвить в текст (например «Одесса») — в переданном списке Группы 1 явно не названо; при необходимости добавить в маппинг отдельной строкой.*

#### Текущая реализация (2026-04-05): детерминированный mapping без текстовых эвристик

- Для `operation/property_type` в импорте OLX **не используется** парсинг `title/description`.
- Порядок резолва: `category_id` (конфиг) -> явные `attributes` (`contract_type`, `property_type_houses`, `property_type_land`, `comm_re_*`, `apartments_*`) -> `null`.
- Актуальные `category_id` правила (`data/olx/category-map.json`):

| `category_id` | `operation` | `property_type` |
|---|---|---|
| `21` | `sale` | `parking` |
| `330` | `rent` | `house` |
| `1602` | `sale` | `house` |
| `1608` | `sale` | `land` |
| `1758` | `sale` | `apartment` |
| `1760` | `rent` | `apartment` |
| `3681` | `sale` | `commercial` |
| `3684` | `sale` | `commercial` |
| `3686` | `sale` | `commercial` |
| `3688` | `sale` | `commercial` |
| `3690` | `rent` | `commercial` |
| `3692` | `rent` | `commercial` |
| `3701` | `rent` | `commercial` |

- Подтверждённые `district_id` (Одесса): `85=Киевский`, `87=Малиновский`, `89=Приморский`.
- Для записей с `district_id = null` используется подтверждённый fallback по `city_id` (например: `44411=Лиманка`, `44353=Авангард`, `43857=Фонтанка`, `43791/43795=Крыжановка`, `43097=Маяки`).

### ГРУППА 2 — ОПИСАНИЕ (обратная сторона карточки)

Забираем и сохраняем **структурно** в **`features.display_specs`**; **в фильтрах не используем** (только отображение / будущее автозаполнение текста).

| Логическое поле | Источник OLX | Назначение |
|-----------------|--------------|------------|
| **Street** | `location.street` **или** `attributes`: **`street_address`** | Улица (в OpenAPI у `location` нет `street` — ориентир на фактический ответ API и `attributes`). |
| **Kitchen area** | **`kitchen_area`** | Площадь кухни, м². |
| **Total floors** | **`total_floors`** | Этажность здания. |
| **Heating** | **`heating`** | См. примеры `value` в §C (`own_boiler-house`, `individual_electro`). |
| **Repair type** | **`repair`** | Часто **код** в `value` (пример: `"2"`); человекочитаемая метка — по справочнику OLX. |
| **Мебель** | **`furnish`** | Пример: `yes` — для описания карточки. |
| **Планировка** | **`layout`** | Пример: `studio`. |
| **Санузлы** | **`bathroom`**, редко **`bathroom_5`** | Для описания. |
| **Тип объекта (дома)** | **`property_type_houses`** | Пример: `house`. |
| **Участок** | **`land_area`** | м². |
| **Условия сделки** | **`contract_type`** | Пример: `values`: `["assignment"]` (цессия). |
| **Животные** | **`pets`** | Пример: `values`: `["yes_small_dog"]`. |
| **Класс недвижимости (не «балкон»)** | **`apartments_dev_type`** | `comfort` \| `business` — для описания / сегментации, не путать с comfort-удобствами. |
| **Infrastructure** | `attributes`: **`infrastructure_within_500_meters`** | Объекты инфраструктуры рядом. |
| **Landscape** | `attributes`: **`landscape_within_1_km`** | Море, парк и т.д. в радиусе. |

### ГРУППА 3 — АРХИВ (только `raw`)

Всё перечисленное **не обрабатываем для логики фильтров и не выводим как отдельные продуктовые поля**; **полный объект объявления** по-прежнему сохраняется в **`properties.raw`**.

| Что относим к архиву | Источник / комментарий |
|----------------------|-------------------------|
| **Negotiable** | `price.negotiable` (торг). |
| **Trade** | `price.trade` (обмен). |
| **Advertiser type** | `advertiser_type` (`private` / `business`). |
| **Coordinates** | `location.latitude`, `location.longitude` (как «не используем в фильтрах» по продуктовому списку; при необходимости позже вынести в актив). |
| **Contact info** | `contact.name`, `contact.phone`. |
| **Multimedia** | `attributes` / поле **`multimedia`** (Wi‑Fi, ТВ и т.д. — уточняется фактический `code` в категории). |
| **Furniture** | **`furniture`** (мебель). |
| **Household appliances** | **`household_appliances`** (техника). |
| **External / служебные идентификаторы** | `id`, `url`, `external_id` — не участвуют в **фильтрации**; **`id`** технически нужен для связи записи с OLX (например `external_id` в БД); в сущности «архив» означает: **нет отдельной бизнес-обработки поля**, кроме сохранения сырья. |

**Всё остальное** из ответа OLX (статус, даты, `salary`, `courier`, `images`, текст `title`/`description` целиком, неразобранные `attributes`, …) либо покрывается группами 1–2 при маппинге, либо остаётся **в составе полного JSON в `raw`**.

## Часть C. Реальные `attributes[].code` (манифест для маппера)

Коды **не из OpenAPI**, а из **фактических ответов** Partner API в вашей базе (`properties.raw.advert.attributes`).

### Как получить таблицу

1. Локально или на машине с доступом к Railway-Postgres:
   ```bash
   cd Voice-Widget-Backend
   DATABASE_URL="postgresql://..." npm run analyze:olx-attributes
   ```
2. Скрипт: `scripts/analyzeOlxRawAttributes.js` — выбирает **последние 20** строк с `external_id ILIKE 'OLX_%'`, собирает все `code`, частоты и примеры `value` / `values`.
3. Результат пишется в **`OLX_ATTRIBUTE_CODES_SNAPSHOT.md`** (перезапись) и дублируется в stdout.
4. Перенесите из снимка в **таблицу ниже** утверждённые строки (после ревью; эвристика скрипта — только подсказка).

> **Статус:** заполнено по выгрузке **10 объявлений** `OLX_*` из чата (2026-04-03): новостройки/квартиры (`primary_market`, `zkh`), аренда/студии, дом (`property_type_houses`), объявление без `zkh`.

### Компактный SQL: все коды по всем OLX_ в базе

Чтобы не копировать огромные JSON, выполни в `psql` и пришли **весь** результат (он короче):

```sql
SELECT
  elem->>'code' AS code,
  COUNT(*) AS rows_with_code,
  MAX(elem->>'value') FILTER (WHERE elem->>'value' IS NOT NULL AND elem->>'value' <> '') AS sample_value
FROM properties,
     LATERAL jsonb_array_elements(raw::jsonb -> 'advert' -> 'attributes') AS elem
WHERE external_id ILIKE 'OLX_%'
GROUP BY 1
ORDER BY rows_with_code DESC, code;
```

Если `raw` не `jsonb`, сначала: `raw::text::jsonb`.

Полный JSON одного объявления без обрезки:

```sql
\pset format wrapped
\pset columns 120
SELECT jsonb_pretty(raw::jsonb -> 'advert' -> 'attributes')
FROM properties
WHERE external_id = 'OLX_918995812';
```

## Часть D. Базовые маппинги UI (апрель 2026)

Этот блок фиксирует **текущую продуктовую интерпретацию** значений OLX для карточек, чтобы при масштабировании на другие города/страны было понятно, от какой базы мы стартовали.

### D.1 Правила форматирования на карточке

- `Цена за м²` отображается в коротком формате:  
  `Цена за м²: 1,701 $` (вместо `USD/m²`).
- `Жилой комплекс` сокращён до `ЖК`:  
  `ЖК: Корфу`.
- Булевы признаки выводим только в позитивном виде:
  - `true` -> `есть` / `є`
  - `false` / `no` / `нет` / `ні` -> **не выводим строку**.

### D.2 Маппинг `heating` (OLX -> UI)

| OLX value | RU | UA |
|---|---|---|
| `own_boiler-house` / `own_boiler_house` | своя котельная | власна котельня |
| `individual_gas` | индивидуальное газовое | індивідуальне газове |
| `centralized` / `central` | централизованное | централізоване |
| `electric` | электрическое | електричне |
| `no_heating` | без отопления | без опалення |

Если приходит неизвестное значение `heating`, показываем его как есть (без потери данных).

### D.3 Маппинг `repair` (OLX -> UI)

| OLX value | RU | UA |
|---|---|---|
| `1` | авторский проект | авторський проєкт |
| `2` | евроремонт | євроремонт |
| `4` | жилое состояние | житловий стан |
| `6` | код OLX 6 (временная подпись) | код OLX 6 (тимчасовий підпис) |
| `repaired` | с ремонтом | з ремонтом |
| `needs_repair` | требует ремонта | потребує ремонту |

Если приходит неизвестное значение `repair`, показываем его как есть.

### D.4 Примечание по источнику истинности

- Бизнес-мэппинг категории/операции/типа остаётся детерминированным через `category_id` и `attributes` (без text-эвристик).
- Этот раздел описывает именно **UI-слой интерпретации** (читабельные подписи/форматы), а не первичную нормализацию в БД.
